## Phase-Scoping Convention

The project uses three phase-declaration patterns:

### Pattern 1: Single-Phase Checks
When a control applies to exactly one phase (modeled on C-0007, C-0009).

```javascript
if (phase !== N) {
  return { id: 'C-XXXX', status: 'SKIP', detail: 'required only at phase N (agent-name)' };
}
```

### Pattern 2: Multi-Phase Range Checks
When a control applies to a range of phases (modeled on C-0011).

```javascript
if (phase < N || phase > M) {
  return { id: 'C-XXXX', status: 'SKIP', detail: `required only at phases N-M; phase ${phase} is outside range` };
}
```

### Pattern 3: Scope-Based Checks
When a control applies based on manifest field, not phase number (modeled on C-0006, C-0010).

```javascript
if (!manifest.compliance_scopes?.includes('target')) {
  return { id: 'C-XXXX', status: 'SKIP', detail: 'required for target-scoped stories only' };
}
```

## Check-by-Check Decisions

### C-0014: Compliance Scope Declaration

**Pattern:** Single-phase (Pattern 1)  
**Phase:** 1 (Product Owner)  
**Rationale:** Scope is declared by PO at story inception (phase 1). Later phases assume scope already known. Universal across all frameworks.

**SKIP Reasons:**
- Phase ≠ 1: "required only at phase 1 (product owner)"
- Phase 1 but not scoped: "story is not compliance-scoped"

**Defect Lane:** ✅ FULL (phase 1 included)

**Artifacts (one per framework):**
- `config/cjis-application-profile.json`
- `config/hipaa-application-profile.json`
- `config/soc2-application-profile.json`
- `config/nibrs-application-profile.json`

---

### C-0015: Compliance Evidence Present

**Pattern:** Multi-phase range (Pattern 2)  
**Phases:** 8+ (security-engineer, technical-writer, release-manager)  
**Rationale:** Evidence (prescan.json) generated by phase 7. Security engineer (phase 8) validates it exists and is valid.

**SKIP Reasons:**
- Phase < 8: "required at phase 8+ (security engineer)"
- Not scoped: "story is not compliance-scoped"

**Defect Lane:** ⚠️ DOCUMENTED GAP
- Defects skip phase 7 (E2E testing) → prescan.json never created
- Gap consequence: No compliance code scanning for defects
- **Decision:** Accept gap (documented, not silent)
- **Mitigation:** Add phase 7 to defect workflow OR create parallel prescan.json path at phase 5

**Artifact:** `.keel/state/<story>/prescan.json` (created by phase 7)

---

### C-0016: Compliance Evidence Fresh

**Pattern:** Multi-phase range (Pattern 2)  
**Phases:** 8+ (security-engineer, technical-writer, release-manager)  
**Rationale:** Evidence freshness validated at phase 8. Ensures evidence not stale (7-day threshold).

**SKIP Reasons:**
- Phase < 8: "required at phase 8+ (security engineer)"
- Not scoped: "story is not compliance-scoped"

**Defect Lane:** ⚠️ DOCUMENTED GAP (same as C-0015)
- Defects skip phase 7 → prescan.json never created
- **Decision:** Accept gap (linked to C-0015 mitigation)

**Artifact:** `.keel/state/<story>/prescan.json` (timestamp check)

---

### C-0017: Compliance Pattern Provenance

**Pattern:** Scope-based (Pattern 3)  
**Scope:** All compliance frameworks (CJIS, HIPAA, SOC2, NIBRS) — all phases  
**Rationale:** Pattern governance orthogonal to phase. Any compliance-scoped story must use sourced/approved patterns. Can run at any phase. Universal across frameworks.

**SKIP Reasons:**
- No scopes declared: "No compliance scopes declared"
- Unknown scope: (silently skipped, allows future framework additions)

**Defect Lane:** ✅ FULL
- Applies if defect is any compliance-scoped (CJIS, HIPAA, SOC2, NIBRS)
- Scope-based (not phase-based) → no defect gap

**Artifacts (one per framework):**
- `config/cjis-data-element-registry.json` (CJIS patterns)
- `config/hipaa-data-element-registry.json` (HIPAA patterns)
- `config/soc2-control-registry.json` (SOC2 controls)
- `config/nibrs-pattern-registry.json` (NIBRS patterns)

### C-0018: Compliance Control Terminal State

**Pattern:** Multi-phase range (Pattern 2)  
**Phases:** 8+ (security-engineer, technical-writer, release-manager)  
**Rationale:** Controls evaluated by security engineer (phase 8). Must reach terminal state (PASS, WAIVED) before release.

**SKIP Reasons:**
- Phase < 8: "required at phase 8+ (security engineer)"
- Not scoped: "story is not compliance-scoped"

**Defect Lane:** ✅ FULL
- Defect phase 8 included ✓
- Controls evaluated in defect workflows

**Artifact:** `.keel/state/<story>/compliance-control.json` (created by phase 8)
